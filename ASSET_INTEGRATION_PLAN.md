## 1. Summary

- Today the whole playable world is plain Parts generated by code (`src/server/Services/MapService.luau`) from a text grid (`src/server/Map/StationLayout.luau`). No meshes, no imported models, and no textures beyond built-in materials.
- Gameplay never depends on what an object *looks like*. It finds map objects by **CollectionService tags and attributes**. Visuals can therefore be replaced without touching objectives, the Echo AI, saving, or remotes, as long as the tags stay.
- **Claude Code cannot insert Creator Store assets into the project by itself.** Creator Store models must be inserted in Roblox Studio (Toolbox) by you, then saved into the repo as model files. From there everything can be automated: syncing, safety scanning, placement and fallbacks.
- **Research finding:** many free "props" on the store are keyword-stuffed uploads from brand-new accounts that claim "No scripts" while actually containing scripts and extra audio. These are the usual carriers of backdoors. Vetting is mandatory (section 4).
- The most trustworthy free source is **Roblox's own official packs**. Ten were checked on the store and are recorded in the catalog. They cover architecture, forest, outdoor utilities, house and antique props, and sci-fi facility interiors. They do **not** cover modern office electronics, a broadcast console, server racks, electrical panels or generators. Those must be sourced from vetted third-party creators or custom-built.

## 4. Asset safety and quality rules

Every imported asset goes through all of these. An asset that fails any rule is **Rejected** in the catalog.

1. **Source:** prefer `@Roblox` official packs. For third-party creators, prefer established accounts with a history of assets and reviews. **Reject** keyword-stuffed titles ("Computer Desk Monitor Tower PC Setup Computers Old") from new accounts.
2. **Store page check:** the script count must be **0** for a decorative prop, or match the description exactly. Audio in a static prop is a red flag. Record creator, created date, triangle count, script count and audio count in the catalog.
3. **Offline audit (after saving to the repo):** `tools/asset_audit.luau` (built in Stage B) will:
   - list every Script, LocalScript and ModuleScript, RemoteEvent and RemoteFunction, Sound, and `require(<number>)`;
   - flag `getfenv`, `setfenv`, `loadstring`, `HttpService`, `TeleportService`, `MarketplaceService` and `InsertService` use, and obfuscated strings;
   - **strip all scripts by default** and write a cleaned copy, unless the asset is explicitly whitelisted;
   - report part count, MeshPart count and texture count.
4. **Never run asset scripts.** Interactivity is always rewritten using our own server-validated systems.
5. **Performance:** see the budgets in section 7. Oversized models are simplified in Studio or rejected.
6. **Licensing:** Creator Store assets can be used in Roblox experiences under Roblox's terms. Synty packs published by Roblox state they are licensed for any Roblox game. Note any creator-specific credit requests in the catalog.

## 5. Proposed asset pipeline

```
Studio Toolbox ──(you: Get Model, delete unwanted parts)──▶ Save selection to file
      │
      ▼
assets/raw/<Kit>/<Name>.rbxm          (not synced; git-ignored until audited)
      │   lune run tools/asset_audit assets/raw      ← offline safety + size report
      ▼
assets/props/<Kit>/<Name>.rbxm        (cleaned: no scripts, anchored, collision set)
      │   Rojo syncs to ServerStorage.Props
      ▼
PropService.place("Kit/Name", cframe)  → clones the model; if it's missing, builds today's primitive
```

- **Fallbacks keep the game playable at every step:** if a prop file isn't there yet, the current primitive is used. The game never breaks because an import hasn't happened.
- **Naming:** `assets/props/<Kit>/<PropName>.rbxm`, for example `Office/DeskMetal.rbxm`. Each model has its `PrimaryPart` set and its pivot at floor-centre-back (against the wall), so code can place it consistently.
- **Prop rules** (applied by the audit, re-checked by `PropService`): everything anchored; `CanTouch = false`; `CanQuery = false` for small decor; `CollisionFidelity = Box` or `Hull` for complex meshes; `CastShadow = false` for small items.
- **Interactive objects** keep a simple tagged part (the "hook") that our scripts use. The model is just the visuals around it. For example, `FusePanel` stays a tagged part, and the breaker-box model is placed so the hook sits behind its door.

## 6. Map construction: decision needed

The current builder makes everything from the text grid. For a believable station there are two realistic routes:

| | **A. Code-built kit** | **B. Hand-built in Studio, hooked up by tags** (recommended) |
|---|---|---|
| How | Keep the grid for gameplay. Rewrite the builder to draw thin walls, door frames, windows and ceiling tiles, and place props from a per-room "dressing" data file | You build the station in Studio from kit pieces and props. It's saved as `Station.rbxm` in the repo and synced by Rojo. Gameplay finds it by tags, as it already supports (`MapService` uses an existing `Workspace.Station`) |
| Visual quality | Good and consistent, but tends to look procedural and grid-aligned | Best: free placement, real composition, storytelling detail |
| Who does the work | Mostly Claude Code; you import props | Mostly you in Studio. Claude Code writes the tag contract, validator, room volumes, interactions and props spec |
| Risk | Grid limits (8-stud cells, flat single floor, no stairs or basement) | Tagging mistakes. Mitigated by an automatic **map validator** that checks every required tag and attribute and test-paths the Echo |
| Needed code work | Builder rewrite, dressing data, PropService | Room volumes (replace grid room lookup), validator, PropService (for spawned items), sign/lamp room attributes from volumes |

**Recommendation: B.** It's the only route to "a carefully designed 3D horror game" rather than a decorated grid, and it supports the basement and outdoor areas that Chapter 1 now needs. The generated grid map stays as a fallback and as the test map for unit tests.

## 8. Echo navigation rules for new geometry

The Echo uses `PathfindingService` with **AgentRadius 2** and **AgentHeight 10**, and cannot jump or climb.
- Doorways and corridors where the Echo may go: **≥ 6 studs clear width**, **≥ 11 studs clear height**.
- Stairs: low, regular steps (≤ 1 stud rise) or ramps. Test that a path is found up and down.
- Furniture: set `CanCollide = false` on small clutter. Large furniture keeps collision so the Echo walks around it.
- Doors: open doors must not block paths. Use `PathfindingModifier` (`PassThrough`) on doors that are open for gameplay.
- **Validation tool (Stage D):** a Studio-only dev command that computes paths between every pair of `EchoPatrol` markers and lists failures, so map edits can be checked in seconds.
